# STARK App v2 SAFE

A workspace demonstrating STARK proof generation and verification using the stwo library.

## 🔒 Security Features

**This implementation is SAFE for production use.** It uses:

- ✅ Transition constraints between rows (row[i] → row[i+1])
- ✅ Boundary selector to handle circular domain wrap-around
- ✅ Forces continuous Fibonacci sequence - cannot skip values!

**Key improvements over stark_appv2:**

| Feature | stark_appv2 (UNSAFE) | stark_appv2_safe (SAFE) |
|---------|---------------------|------------------------|
| Transition constraints | ❌ None | ✅ row[i+1].a == row[i].b |
| Boundary handling | ❌ None | ✅ is_not_last selector |
| Can skip rows | ✅ Yes (vulnerable!) | ❌ No (enforced continuity) |

This version enforces that the entire trace forms one unbroken Fibonacci sequence.

## Architecture

This workspace consists of three crates:

- **circuit** (library) - Defines the Fibonacci circuit that both prover and verifier agree on
- **prover** (binary) - Generates STARK proofs for Fibonacci sequences
- **verifier** (binary) - Verifies STARK proofs

## Building

```bash
cargo build
```

## Running

### Prover

Generate a proof with default parameters (log_size=8, f(0)=1, f(1)=1):

```bash
cargo run --bin prover
```

Generate a proof with custom parameters:

```bash
cargo run --bin prover -- <log_size> <initial_a> <initial_b>
```

Examples:
```bash
# 64 rows, starting with f(0)=2, f(1)=3
cargo run --bin prover -- 6 2 3

# 256 rows, starting with f(0)=1, f(1)=1
cargo run --bin prover -- 8 1 1
```

The prover will:
1. Generate the Fibonacci trace
2. Create a STARK proof
3. Save proof metadata to `proof_metadata.json`

### Verifier

Verify the proof generated by the prover:

```bash
cargo run --bin verifier
```

The verifier will:
1. Read proof metadata from `proof_metadata.json`
2. Regenerate the trace and proof (since full serialization is not yet implemented)
3. Verify the proof

## Circuit Details

The circuit implements a simple Fibonacci sequence constraint:

```
f(n) = f(n-1) + f(n-2)
```

Each row contains 3 columns:
- Column 0: f(n-2)
- Column 1: f(n-1)
- Column 2: f(n)

## Limitations

- **NO Transition Constraints**: This vertical layout cannot be made safe with row-to-row transition constraints because:
  - The stwo framework's `EvalAtRow` trait operates on individual rows
  - While `next_interaction_mask` exists for logup/interaction traces, it doesn't support accessing next row values for original trace columns in vertical layouts
  - The framework is designed for horizontal (wide) layouts where constraints flow across columns within the same row

- **Proof Serialization**: The full STARK proof serialization is not yet implemented. The verifier currently regenerates the proof from the parameters stored in `proof_metadata.json`. In a production system, the entire proof would be serialized and the verifier would not need to regenerate it.
